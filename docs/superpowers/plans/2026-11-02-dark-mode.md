# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** System / Light / Dark / Dugout themes for the signed-in web and mobile apps. Dark is a new neutral charcoal palette. Public pages, auth screens and live scorekeeping stay light.

**Architecture:** Instead of hand-editing ~5,300 hardcoded Tailwind color classes, we **remap the palette Tailwind already uses**. `white`, `gray-*` and the common hue scales (`red`, `amber`, `brand`, …) become CSS-variable-backed per role: background, text and line. In Light every variable equals today's hex, so nothing changes. In Dark and Dugout they resolve to dark equivalents. One pure-TS palette module in `@baseball/shared` is the single source of truth. Both Tailwind configs consume it: web through a `data-theme` attribute plus CSS variables, mobile through NativeWind `vars()`. Manual work shrinks to what the remap can't reach: hex literals, inline styles, charts, and per-screen visual fixes.

**Tech Stack:** Next.js 14 + Tailwind 3.4 (web), Expo SDK 51 + NativeWind 4.2 + react-native-css-interop 0.2 (mobile), Jest (ts-jest for web/shared, jest-expo for mobile).

**Spec:** `docs/superpowers/specs/2026-11-02-dark-mode-design.md`

## Global Constraints

- Theme preference values: `system | light | dark | dugout`; default `system`; System resolves only to `light` or `dark`.
- Preference is stored per device: web `localStorage['dos_theme']` (existing key), mobile SecureStore key `dos_theme`. No database change.
- Signed-in app only. Public routes (`/`, `/l/…`, `/p/…`, `/leagues`, `/about`, `/demo`, `/offline`), web `(auth)` and `/auth/*`, and mobile `(auth)` and `auth-callback` always render Light.
- Scorekeeping content stays Light: web `apps/web/src/app/(app)/games/[gameId]/score/`, mobile `apps/mobile/app/(tabs)/schedule/games/[gameId]/score.tsx` + `src/features/scoring/` modals. App chrome around them (sidebar, tab bar, header, status bar) follows the theme.
- Parent live view (web `(app)/live/[gameId]`, mobile `schedule/games/[gameId]/live.tsx`) follows the theme.
- Team custom colors (web `Sidebar.tsx` `primaryColor`/`secondaryColor`) apply in Light only.
- Light must render pixel-identical to today on every page.
- Contrast in Dark and Dugout: `fg` and `fg-muted` ≥ 4.5:1 on every surface; `fg-subtle` ≥ 3:1; white text on `--app-brand` ≥ 4.5:1; form-control borders ≥ 3:1. Decorative dividers exempt. Light tokens are not changed.
- Dark (charcoal) semantic values, from the spec: bg `#0f1115`, surface `#181b22`, surface-2 `#14171d`, surface-raised `#1e222b`, border `#2a2f3a`, border-strong `#3a404d`, fg `#e7e9ee`, fg-muted `#9ba1ad`, fg-subtle `#6b7280`, sidebar-bg `#0a0c10`, sidebar-fg `#e7e9ee`, sidebar-active `#232833`, brand `#2563eb`, brand-2 `#60a5fa`.
- Dugout semantic values are the existing `[data-theme="dugout"]` block in `apps/web/src/app/globals.css`, unchanged.
- No flash of the wrong theme on web first paint or mobile cold start.
- Release per platform: Parts A+B merge and ship as the web release. Part C lives on `feature/dark-mode-mobile` (branched after A+B merge) and merges only when every mobile task is done.
- Repo rules (`CLAUDE.md`): Conventional Commits, commit per task, CodeRabbit review after each part (`coderabbit review --plain --base main`), tests for pure logic.

## Review Focus

1. **A public page viewed by a signed-in user with Dark set must stay light**, including after client-side navigation from a dark app page to a public page (e.g. dashboard → `/l/<slug>`). → Test in Task B3 (`ThemeProvider` re-applies on pathname change) and verification in B8.
2. **New `(app)` routes added later must not silently skip theming or theme a public route.** → Task B3 test walks `src/app/(app)` and `src/app/(auth)` on disk and checks each top-level segment against `isThemedPath`.
3. **Corrupt or old stored values** (`'navy'`, `''`, a value from a future version, or localStorage/SecureStore throwing) must fall back to System, not crash or blank. → Tests in A2 (`parseThemePreference`), B3 (bootstrap script with throwing `localStorage`), and C2 (SecureStore rejects).
4. **OS theme flips while the app is open with System selected** must update live, but must not override an explicit Light/Dark/Dugout choice. → Tests in B3 (matchMedia change event) and C2 (`useColorScheme` change).
5. **Shared scoring components rendered outside the scorer** (`BaserunnerDisplay` in mobile `live.tsx`) must be themed there and light inside the scorer. → Test in C2 (nested `ThemeScope` resolves colors from the nearest scope) and visual check in C6.

## Part A — Shared palette (`@baseball/shared`)

### File structure

```

  palette.ts           light base scales, dark/dugout neutral ramps, semantic tokens
```

**Interfaces:**
- Produces (color-math):

### Task A2: Themed color lookup, variable builder, preference logic

**Interfaces:**

  - `themedColor(theme: ResolvedTheme, role: ColorRole, color: PaletteColor | 'white' | 'black', shade?: Shade): string`. Returns hex. Rules:
    - `light`: `BASE_COLORS[color][shade]`; `white` → `#ffffff`; `black` → `#000000`.
    - `gray` in dark/dugout: `NEUTRAL_RAMPS[theme][role][shade]`. `white`: bg → ramp `bg.white`, fg/line → `#ffffff`. `black`: fg → ramp `black`, bg/line → `#000000`.

      - line: 50 → `mixHex(H(500), S, 0.18)`, 100 → `0.25`, 200 → `0.35`, 300 → `0.45`; others = light value.
  - `themeVarName(role: ColorRole, color: PaletteColor | 'white' | 'black', shade?: Shade): string` → `--dos-${role}-${color}` or `--dos-${role}-${color}-${shade}`
  - `semanticVarName(token: SemanticToken): string` → `--dos-app-${token}`
  - `buildThemeVars(theme: ResolvedTheme): Record<string, string>`: every role × (`white`, `black`, every `PaletteColor` × `Shade`) plus every semantic token, values from `rgbChannels(...)`. Memoize per theme.
  - `type ThemePreference = 'system' | ResolvedTheme`; `THEME_PREFERENCES: readonly ThemePreference[]` (order: system, light, dark, dugout); `DEFAULT_THEME_PREFERENCE: ThemePreference = 'system'`
  - `parseThemePreference(raw: string | null | undefined): ThemePreference`. Unknown → `'system'`.
  - `resolveTheme(preference: ThemePreference, systemPrefersDark: boolean): ResolvedTheme`

Emits `buildThemeVars('light')` under `':root, [data-theme="light"]'` (or `':root'` alone when `themeSelectors` is false). When `themeSelectors` is true it also emits `[data-theme="dark"]` and `[data-theme="dugout"]`.
